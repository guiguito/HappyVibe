# Linux (PRD §4)

- **Never add a `deb:` block with `depends`.** It REPLACES electron-builder's defaults instead of
  extending them, and those defaults carry `libsecret-1-0` (MCP OAuth's keychain) plus `libgtk-3-0`,
  `libnss3`, `libxss1`, `libxtst6`, `xdg-utils`, `libatspi2.0-0`, `libuuid1`. The result installs
  cleanly and won't launch. `tests/linux-package.test.ts` asserts the absence AND that upstream still
  defaults to libsecret.
- **Icon grouping is an association problem, and `desktopName` is the one answer.** electron-builder
  derives the installed `.desktop` filename and `StartupWMClass` from `desktopName` in `package.json`,
  and Electron derives its `app_id` from the same field. Keep `desktopName` +
  `linux.syncDesktopName: true`; never hand-write `StartupWMClass` (a copy can only drift).
- `build/icons/` is GENERATED by `npm run icons` from `build/icon.svg`. Load-bearing in
  `scripts/icons.mjs`: no top-level `await` (`app.whenReady()` at module scope deadlocks with no
  output); `createRequire` rather than a static `electron` import; `offscreen: true` (a hidden window
  has no compositor output on macOS, so `capturePage` never settles); ONE capture then resize (a
  window per size fails after the first load, and `capturePage` answers at the DISPLAY scale factor).
- node-pty is compiled on Linux (no prebuild); the N-API binary serves Node and Electron and rides in
  the artifact, so `npmRebuild: false` stays correct. Both arms of `tests/native-modules.test.ts` assert.
- The file tree doesn't live-refresh: recursive `fs.watch` doesn't exist on Linux, so `watchWorkspace`
  returns early. Accepted ceiling, not a bug.
- x64 only because nothing tests arm64 (`sherpa-onnx` and anydoc do publish linux-arm64) — a different
  reason from Windows, where no upstream binary exists. Keep the two reasons apart.
- Terminal specifics (`/bin/bash` from `pty.process`, `EXEC_FAILED`): `terminals.md`. Measurements:
  `docs/validation/lin1.md`.
