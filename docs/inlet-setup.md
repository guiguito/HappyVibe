Shipped builds carry the old key and IDs, so feedback, crash reports, usage statistics and remote config from any released version stop working once the old install is gone. Remote config fails open (web tools keep working); the rest is simply lost until a new release.

## Recreate checklist

A server key can create neither projects nor keys, so the web-UI steps come first. Everything after runs through the MCP servers.

**Before the wipe**

- [ ] Optional: export what little is there — `export_submissions` (2 Dev submissions), `export_crash_reports` (60 Dev reports), `export_analytics_events` (Dev test events), `export_config_history`. All test traffic.

**In the Inlet web UI (your admin account)**

- [ ] Create projects **HappyVibe Dev** and **HappyVibe Prod**.
- [ ] In each, mint one secret server key (`isk_`) and one publishable key (`ipk_`).

**Point the MCP servers at the new keys**

- [ ] Dev `isk_` → `~/.claude.json` `inlet`; Prod `isk_` → `inlet-prod`. Restart Claude Code.
- [ ] Same keys in `.env` as `FEEDBACK_API_KEY` / `FEEDBACK_API_KEY_PROD`.

**For each project (via MCP)**

- [ ] `create_feedback_database` **General Feedback** → `save_form_draft` (JSON above) → `publish_form`.
- [ ] `create_feedback_database` **Session Rating** → `save_form_draft` → `publish_form`.
- [ ] `create_crash_database` **HappyVibe Dev Crashes** / **HappyVibe Prod Crashes** (default retention matches).
- [ ] `create_analytics_database` **UX Analysis**, timezone `Europe/Paris`, country derivation on (storage defaults match).
- [ ] `create_config_database` **App setup** (60-minute refresh, country derivation on) → `import_config_template` (Dev or Prod JSON above) → `validate_config_draft` → `publish_config`.
- [ ] Dev only: `update_hosted_form` on General Feedback with the settings above (slug `happyvibe`, enabled).
- [ ] Dev only: `create_feedback_database` **Smoke tests** → its JSON → `publish_form`.

**Back in the repo**

- [ ] Update every row of the Repo wiring table.
- [ ] `npm run gate` — `tests/feedback-config.test.ts` and `tests/feedback-secrets.test.ts` check the new values.
- [ ] `tests/feedback-live.test.ts` and `node scripts/crash-probe.mjs` once each against the new install; `npm run dev`, then `get_analytics_live_events` on the new Dev UX Analysis should show `app_installed` / `app_started` within ~10 s.
- [ ] Cut a release, because shipped builds still carry the old key.
