# Terminal (part 1 — user-driven) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real shell in a tab, per workspace, cwd at the workspace root, ungated — PRD §26 part 1.

**Architecture:** `node-pty` in main owns every PTY; main also runs one `@xterm/headless` instance per PTY as the scrollback buffer (three readers: live renderer, re-attaching renderer, and part 2's agent read). The renderer is a view: `@xterm/xterm` in a `:term:<id>` tab, a third prefix beside `:chat:` and file paths in the existing 2×2 pane grid. The whole tab layout becomes persisted, which is what makes terminals survive ⌘R.

**Tech Stack:** node-pty 1.1.0 · @xterm/xterm 6.0.0 · @xterm/headless 6.0.0 · addon-fit 0.11.0 · addon-serialize 0.14.0 · addon-search 0.16.0 · addon-web-links 0.12.0

## Global Constraints

- **PRD §26 is the spec.** Every decision below is already locked there; do not re-litigate.
- **`node-pty` ships N-API prebuilds** (`prebuilds/darwin-arm64/{pty.node,spawn-helper}`) — verified. It therefore needs **no** `electron-rebuild`, works identically under vitest's Node and under Electron, and `install-app-deps` is irrelevant to it.
- **`spawn-helper` loses its executable bit through npm** — verified: it installs `-rw-r--r--` and every `pty.spawn` fails with `posix_spawnp failed`. A `postinstall` `chmod +x` is REQUIRED and is Task 1. This is the packaging risk the spec predicted, and it bites in dev before it bites in a build.
- **Streaming bytes never pass through React state** (§7 perf invariant). PTY data goes `ipcRenderer.on` → `term.write()` directly.
- **Content is mounted once and placed by CSS `grid-area`** (`tabs.ts:32-35`). A terminal must be a flat grid child in `App.tsx`'s mount list, never nested in a pane component — a remount detaches the PTY listener and loses the emulator.
- **Never `npm run lint` / `npm run format`** (CLAUDE.md — scaffold leftovers, 85%-of-repo diff).
- **Never pipe a test run to `tail`/`grep`** (CLAUDE.md). Redirect to a log, then grep the log.
- Gate = `npm run gate`. `npm run live:why` decides whether the live batch is required; nothing here touches `pi-runtime/extensions/`, `src/main/pi/` or a live test file, so it should print nothing — **check it and say so**, don't silently omit.

// node-pty's prebuilt spawn-helper arrives without its executable bit through
// npm, and pty.spawn then fails with "posix_spawnp failed" — in dev, not only
// when packaged. Idempotent; a no-op on Windows, which has no spawn-helper.
import { chmodSync, existsSync, readdirSync, statSync } from "node:fs";
import path from "node:path";

const prebuilds = path.join("node_modules", "node-pty", "prebuilds");
if (existsSync(prebuilds)) {
  for (const dir of readdirSync(prebuilds)) {
    const helper = path.join(prebuilds, dir, "spawn-helper");
    if (!existsSync(helper)) continue;
    const mode = statSync(helper).mode;
    if (!(mode & 0o111)) {
      chmodSync(helper, mode | 0o111);
      console.log(`[fix-pty-helper] chmod +x ${helper}`);
    }
  }
}
```

/** Paths never start with ":", so this cannot collide with one. */
export const TERM_PREFIX = ":term:";
export const termTab = (terminalId: string): TabId => `${TERM_PREFIX}${terminalId}`;
export const isTermTab = (id: TabId): boolean => id.startsWith(TERM_PREFIX);
/** The terminal a term tab belongs to, or null. */
export const terminalOf = (id: TabId): string | null =>
  isTermTab(id) ? id.slice(TERM_PREFIX.length) : null;
```

```ts
/** Every open file path across every pane (for the flat mounted FileTab list).
 *  A tab is a file only if it is neither a chat NOR a terminal — this function
 *  also feeds the fs watch targets and §9's open-files context block, so a
 *  sentinel leaking in here reaches the model. */
export function allFiles(t: WorkspaceTabs): string[] {
  const out: string[] = [];
  for (const i of liveSlots(t))
    for (const id of t.panes[i]!.tabs) if (!isChatTab(id) && !isTermTab(id)) out.push(id);
  return out;
}
```

## Verification

`npm run gate` (build → both typechecks → the non-live suite) must be green, and `npm run live:why` must be checked and its result stated — nothing here touches `pi-runtime/extensions/`, `src/main/pi/` or a live test file, so it is expected to print nothing.

### Observable GUI assertions

Not "needs a GUI pass" — these are what must be **true on screen**, checkable without re-deriving the design.

**Positive claims, and the surface each is observed on**

1. *Centre pane, any workspace* — ⌘T adds a tab titled `zsh` and a shell prompt appears in it. Typing `echo hello` and pressing Enter prints `hello` **in the tab**, not in a devtools log.
2. *Centre pane* — while `sleep 30` runs, the tab title reads **`sleep`**, and reverts to `zsh` when it finishes.
3. *Centre pane* — the pane's `+` menu shows exactly three entries, in order: **New session · New terminal (⌘T) · Open file…**
4. *Centre pane, split layout* — dragging the terminal tab from pane A to pane B keeps its scrollback and its live prompt. **The buffer does not clear and the prompt still accepts input** — that is the mount-once invariant, and a remount is exactly what it would break.
5. *Centre pane* — after ⌘R, the terminal tab **is still there, with its scrollback**, and so are the chat and file tabs and the pane sizes. The prompt still responds.
6. *Centre pane* — ⌘W on a terminal running `sleep 30` shows a confirm naming **`sleep`**; cancelling leaves it running, confirming closes the tab and the process is gone (`ps` shows no orphan).
7. *Settings → Terminal* — the three style swatches render the **real** palettes; switching to Paper turns a **live, already-open** terminal cream without clearing its buffer.
8. *Workspace settings → danger zone* — Forget or Delete a workspace with two open terminals; both tabs disappear and both PTYs are gone.
9. *Settings → Audit log* — opening a terminal produces **exactly one** `terminal.open` row. Typing ten commands produces **no further rows**.

**Absence assertions — named, because an absence cannot be screenshotted**

10. *Chat pane, context bubble → Conversation* — with a terminal tab open, the open-files block contains **no entry beginning `:term:`**. This is the `allFiles` defect; the surface that would expose it is the **context panel**, not the terminal.
11. *File drawer* — opening a terminal adds **no** entry to the file tree and **no** editor tab; the drawer looks exactly as it did.
12. *Any terminal* — typing `rm -rf /tmp/whatever` and pressing Enter raises **no permission modal**. §26: permissions gate the agent, not the human. A prompt appearing here is a bug, not caution.
13. *Settings → All Tools* — the built-in tools block still lists exactly **Plan mode** and **ask_user**. There is **no "Terminal" entry** — that is part 2, and a human's own terminal is not a model capability.

**The one regression this design risks, as a sequence**

14. Open two terminals and a chat in pane A. Split vertically. Drag terminal #2 to pane B. Close pane B with ✕ (its tabs merge back into A). Now close terminal #1 with ⌘W. **Expected:** terminal #2 is still alive with its buffer, pane A did not collapse, and no PTY leaked (`ps` shows exactly one shell). The risk is `closePane`'s merge plus `normalize`'s collapse running while a mounted emulator is being re-placed by grid-area — the one path where a tab changes pane *without* a drag.
