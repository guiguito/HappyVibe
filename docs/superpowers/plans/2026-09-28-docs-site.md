# HappyVibe user guide — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the HappyVibe user guide at `https://happyvibe.dev/docs/`, with one page per sidebar screen, a help link on every screen that opens its page in the app, and plain-Markdown copies for AI agents.

**Architecture:** An Astro Starlight site lives in this repo at `docs/guide/` as its own npm project. It imports the app's design tokens from `src/renderer/src/theme.css`, which is split out of `styles.css` in Task 1, so the guide never keeps a copy. The build is copied into the website repo's `public/docs/` and deployed with the landing page on Firebase. In the app, `docsLinks.ts` maps each sidebar screen to its page, and one `DocsLink` row under every settings screen opens that page in a browser pane.

**Tech Stack:** Astro + `@astrojs/starlight`, `@astrojs/starlight-tailwind` with Tailwind v4 (only to read the app's `@theme` block), Pagefind (Starlight's built-in search), vitest for the app-side tests, `node:assert` for the build check, Firebase Hosting.

**Spec:** Notion, "Documentation" — https://app.notion.com/p/3e8d33dfffca80a28eb9f1a83b4b2e8a. Read it before starting. The **Media** section there is the brief for the separate agent that shoots the screenshots and videos (Task 16 waits for them).

**Two repos.** Part A (Tasks 0–17) runs in this repo, HappyVibe. Part B (Tasks 18–21) runs in the website repo, `HappyVibeWebsite`, checked out beside it (`../HappyVibeWebsite` from this repo's root).

## Global Constraints

- The guide's address is `https://happyvibe.dev/docs/`: Astro `site: "https://happyvibe.dev"`, `base: "/docs"`, `trailingSlash: "always"`.
- URLs are flat, one per page, named after the screen's label in kebab case. The full set:
  - Get started: `install`, `first-launch`, `connect-a-model`, `first-session`, `approve-a-tool-call`
  - Everyday use: `workspaces-and-sessions`, `session-view`, `files-and-changes`, `schedules` (Task 13A)
  - Pinned: `models`
  - Abilities: `built-in-tools`, `memory`, `plugins`, `skills`, `prompts`, `mcp`, `agents`
  - Control: `system-prompt`, `permissions`, `agent-tools`
  - App features: `terminal`, `voice`, `ai-autofill`, `keyboard-shortcuts`, `privacy`
  - The record: `stats`, `audit-log`, `changelog`
- A reference page's `title` is its screen's sidebar label, exactly as `NAV` in `src/renderer/src/components/Sidebar.tsx` spells it.
- English only, one version.
- Light theme only.
- Colours, fonts and shadows come from `src/renderer/src/theme.css` by import. Never write a colour value into `docs/guide/`.
- The guide's dependencies go in `docs/guide/package.json` only. The app's `package.json` gains nothing.
- Every fact comes from the code, and every quoted UI string matches the code character for character.
- Voice and banned words: `docs/guide/VOICE.md` (Task 6).
- Until a shot exists, its page holds `<!-- TODO(media): <file> — <Shows line> -->` on its own line; `markdown()` strips it from the agent copies and the build check fails if one leaks.
- Media lives at `docs/guide/public/media/<slug>/<shot-id>.<ext>`, referenced as `/docs/media/<slug>/<shot-id>.<ext>`. Screenshots are PNG. Videos are MP4 (H.264) plus WebM plus a JPG poster.
- **This repo:**
  - Work on branch `feat/docs-site` and never commit to `main`.
  - Every commit is `git commit -s` (DCO).
  - The gate is `npm run gate`.
  - Land with `/land`.
- **Website repo:**
  - Commit and push each task straight to `main`.
  - Pushing does not deploy, because the GitHub Actions deploy is billing-blocked. Deploy with `firebase deploy --only hosting`.
  - Check the live site with a cache buster: `?cb=$RANDOM`.
- **Copy that must be approved first:** the website's "Docs" link and the 404 page's wording go live only after the Notion pitch page carries them (Task 18).

## Review Focus

1. **First run, before any workspace exists.** A help link must still open the guide, in the system browser, and never throw. Covered by Task 8's test "with no workspace, the link falls back to the system browser".
2. **Embed mode.** In the app's pane, `?embed=1` hides the site title, and it must stay hidden when the reader follows links inside the guide. A normal visit on the website must never inherit it. Covered by Task 5's build check and manual step.
3. **A mistyped URL anywhere on the site.** It returns a real 404 status with the 404 page, never the landing page with a 200. Covered by Task 19's local check and Task 21's live check.
4. **Markdown copies with non-ASCII characters** (—, ⌘, …). They must be served as UTF-8, or an agent may read garbled text. Covered by Task 19's `firebase.json` headers and Task 21's `content-type` check.
5. **A screen added to the app later without a guide page.** The suite must fail and name the screen. Covered by Task 8's `docs-links` test and Task 14's `docs-structure` test.

- [ ] **Step 4: Write the build check first** — `scripts/check-build.mjs`

```js
// The built guide, checked against the spec (Notion: Documentation). `npm run build` runs it.
// ponytail: node:assert over dist/, no test framework, because every check is a file read.
import assert from "node:assert/strict";
import { existsSync, readFileSync, readdirSync } from "node:fs";
import { join } from "node:path";

const DIST = new URL("../dist/", import.meta.url).pathname;
const SITE = "https://happyvibe.dev/docs/";
const read = (p) => readFileSync(join(DIST, p), "utf8");
const esc = (s) => s.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
const pages = readdirSync(DIST, { recursive: true })
  .map((f) => f.split("\\").join("/"))
  .filter((f) => f.endsWith("index.html"));
const css = readdirSync(join(DIST, "_astro"))
  .filter((f) => f.endsWith(".css"))
  .map((f) => read(join("_astro", f)))
  .join("\n");

assert.ok(pages.includes("index.html"), "the docs home was not built");
for (const p of pages) {
  const html = read(p);
  const url = SITE + p.replace(/index\.html$/, "");
  assert.match(html, new RegExp(`<link[^>]*rel="canonical"[^>]*href="${esc(url)}"`), `${p}: canonical must be ${url}`);
  assert.match(html, /<meta[^>]*name="description"[^>]*content="[^"]+"/, `${p}: needs a description`);
  assert.ok(!html.includes("<starlight-theme-select"), `${p}: the theme switcher must be gone (light only)`);
  assert.ok(html.includes('dataset.theme = "light"'), `${p}: the light theme must be forced`);
}
assert.ok(existsSync(join(DIST, "sitemap-index.xml")), "no sitemap");
assert.ok(existsSync(join(DIST, "pagefind", "pagefind.js")), "no search index");
assert.ok(existsSync(join(DIST, "favicon.svg")), "no favicon");
assert.match(css, /--color-paper:\s*#faf4e8/, "the app's tokens did not reach the CSS");
assert.match(css, /Gabarito Variable/, "the app's text font did not reach the CSS");

console.log(`docs check: ${pages.length} pages OK`);
```

```ts
import { getCollection, type CollectionEntry } from "astro:content";
import sidebar from "../../sidebar.json";

export const SITE = "https://happyvibe.dev/docs";
export type Page = CollectionEntry<"docs">;
type Item = string | { label: string; items: string[] };

/** Every page with the sidebar section it sits in: the docs home first, then sidebar order. */
export async function orderedPages(): Promise<Array<{ section: string; page: Page }>> {
  const byId = new Map((await getCollection("docs")).map((p) => [p.id, p]));
  const out: Array<{ section: string; page: Page }> = [{ section: "", page: byId.get("index")! }];
  for (const item of sidebar as Item[]) {
    const [section, ids] = typeof item === "string" ? [byId.get(item)!.data.title, [item]] : [item.label, item.items];
    for (const id of ids) out.push({ section, page: byId.get(id)! });
  }
  return out;
}

/** What an agent reads: the page's own Markdown, under its title. */
export const markdown = (p: Page): string => `# ${p.data.title}\n\n${p.body ?? ""}\n`;
```

```ts
import { describe, expect, it } from "vitest";
import fs from "node:fs";
import path from "node:path";
import { GROUPS, NAV } from "../src/renderer/src/components/Sidebar";
import { DOC_SLUG } from "../src/renderer/src/docsLinks";

/**
 * Docs round (2026-09-28): the guide's sidebar mirrors the app's, so a reader
 * never learns a second structure, and a screen added to the app without a
 * guide page fails here by name.
 */
const GUIDE = path.join(import.meta.dirname, "..", "docs", "guide");
type Item = string | { label: string; items: string[] };
const SIDEBAR: Item[] = JSON.parse(fs.readFileSync(path.join(GUIDE, "sidebar.json"), "utf8"));
const group = (label: string): string[] =>
  (SIDEBAR.find((i) => typeof i !== "string" && i.label === label) as { items: string[] }).items;
const title = (slug: string): string => {
  const file = path.join(GUIDE, "src", "content", "docs", `${slug}.md`);
  if (!fs.existsSync(file)) return `(no page at ${slug}.md)`;
  return fs.readFileSync(file, "utf8").match(/^title: (.+)$/m)?.[1] ?? "(no title)";
};

describe("the guide mirrors the app's sidebar (Docs round, 2026-09-28)", () => {
  it("Get started, then Everyday use, then Models pinned, then the app's groups in order", () => {
    expect(SIDEBAR.map((i) => (typeof i === "string" ? i : i.label))).toEqual([
      "Get started",
      "Everyday use",
      "models",
      ...GROUPS.map((g) => g.label),
    ]);
  });

  it("each group lists its screens in the app's order", () => {
    for (const g of GROUPS) {
      expect(group(g.label), g.label).toEqual(NAV.filter((n) => n.group === g.id).map((n) => DOC_SLUG[n.view]));
    }
  });

  it("every screen's page exists and is titled with the screen's label", () => {
    for (const n of NAV) expect(title(DOC_SLUG[n.view]!), n.view).toBe(n.label);
  });

  it("Get started holds the five pages the spec names", () => {
    expect(group("Get started")).toEqual(["install", "first-launch", "connect-a-model", "first-session", "approve-a-tool-call"]);
  });
});
```
